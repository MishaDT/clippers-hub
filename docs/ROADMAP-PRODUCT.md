# ФАЗА 1 · Кампания: бриф, режимы согласования, проверка качества (🔴)

## 1.1 Режимы согласования (быстрый/стандартный/строгий)
- ⬜ Поле `Campaign.approvalMode: FAST | STANDARD | STRICT` `(модели: schema + migration)`.
- ⬜ Логика:
  - FAST — approve платформой (без ручного approve заказчика);
  - STANDARD — approve платформой, спорные → поддержка;
  - STRICT — approve заказчиком (одобрить / на правки / отклонить с причиной), публикация только после approval.
- ❓ **п.3** — дефолт STANDARD?
- DoD: режим выбирается при создании, влияет на flow модерации (Фаза 3).

## 1.2 Расширенный бриф кампании
- 🔧 Дополнить поля (частично есть в `briefJson/rulesJson`): таймкоды исходника, макс. выплата, цель просмотров, стоп-слова, разрешён ли мат/кликбейт/мемы, watermark, субтитры, длительность, язык, регион, режим согласования `(файлы: app/campaigns/new, prisma)`.
- ⬜ Wizard-бриф (см. `docs/ROADMAP.md` D3).
- DoD: бриф достаточен для однозначной нарезки и споров.

## 1.3 Проверка качества кампании до запуска

## Порядок исполнения (MVP)
Фаза 0 (данные/онбординг/аккаунты/уровни) → 1 (бриф/режимы/проверка кампании) → 2 (черновик/модерация) → 3 (approve/правки) → 4 (публикация/трекинг/валидные/срок) → 5 (оплата/escrow) → 6 (лента/совместимость/риск) → 7 (рейтинги/проверенный) → 8 (лидерборды) → 9 (защита/отзывы/комната).

Внутри — сначала ответы на ⚠️ БЛОК 0. Без п.1 (трекинг просмотров) и п.2 (видео-модерация) фазы 2 и 4 проектировать нельзя.

## Главная формула
> Заказчик покупает массовое распространение коротких клипов. Клиппер зарабатывает на публикации на своих аккаунтах. Платформа следит: заказ подходит клипперу, ролик по правилам, просмотры честные, обе стороны защищены.
