# ReelPay — Roadmap 0% → 100% (до launch-ready)

Единый детальный план: твой «План полной доработки» + выводы по конкуренту Insense + приоритет «доверие заказчика».
Позиционирование, которое закрепляем везде:

> **ReelPay — performance-биржа клипов из готового контента. Заказчик задаёт цель по просмотрам и бюджет, платит только за проверенный результат, неизрасходованное возвращается.**
> Insense = наём креаторов и управление UGC-кампаниями. ReelPay = нарезки за реальные просмотры. Не «Insense подешевле», а отдельная категория.

Всё «доверие» держится на корректных деньгах — делаем первым.

- ⬜ Заказчик видит полную стоимость результата; клиппер — чистую выплату и комиссию по лиге.
- ⬜ Обещание доплаты за watermark: либо реализовать в формуле, либо убрать из брифа `(files: lib/money.ts, app/actions.ts createCampaignAction, app/campaigns/[id])`.
- DoD: одна функция-источник; выплата на карточке заказа == фактическое начисление в транзакции (тест).

## A2. Слоты и адресный резерв бюджета
- ⬜ Миграция схемы: `Campaign.maxPaidResults`, `Campaign.reservedBudgetCents`, `Submission.reservedPayoutCents` `(файлы: prisma/schema.prisma + migration)`.
- ⬜ «Взять заказ»: атомарно резервировать ожидаемую выплату под конкретного клиппера (updateMany с условием остатка/слотов).
- ⬜ Кончились слоты или свободный бюджет → заказ нельзя взять (guard в `joinCampaignAction`).
- ⬜ Отмена/истечение/отклонение → резерв возвращается ровно один раз (идемпотентно).
- ⬜ Settlement списывает из `reservedPayoutCents`, а не из общего остатка.
- DoD: одновременное взятие последнего слота двумя клипперами → один резерв, второй получает «слоты закончились» (конкурентный тест).

## Что НЕ делать
- Не превращаться в тяжёлый B2B-SaaS (подписки, managed-services, дорогой pricing) — преимущество ReelPay в низком пороге и оплате за результат.
- Не смешивать демо и реальные метрики.
- Не подключать нейросети в Ридзи.
- Не добавлять новые CSS-костыли в `globals.css`.

## Порядок исполнения (кратко)
A (финансы) → B (доверие) → C (UI/моб + logout + демо) → D (привлечение) → E (удержание) → F (аналитика) → G (QA/релиз).
Внутри A–B — 🔴 P0, до любого продвижения. C — параллельно можно начинать сразу.
