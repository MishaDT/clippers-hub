# ReelPay — индекс экранов и план упрощения интерфейса

Дата аудита: 12 июля 2026. Этот документ — рабочая карта следующего UX-прохода. Он индексирует пользовательские, служебные и административные страницы, фиксирует назначение блоков и указывает, где нужен FAQ, короткая подсказка или полная переработка.

## Общие правила

- Мобильный вертикальный интервал между самостоятельными секциями: `20px`; внутри карточки: `12–16px`; между заголовком и пояснением: `6–10px`.
- На первом мобильном экране остаются одна мысль, один основной CTA и максимум один вторичный CTA.
- Декоративные демонстрации скрываются на телефоне, если повторяют следующий блок или занимают больше половины экрана.
- FAQ добавляется только там, где вопрос мешает выполнить действие. Справочную энциклопедию переносим в `/help`.
- Ответ FAQ: максимум 2–3 коротких предложения; 4 вопроса на экран без раскрытия «Показать ещё».
- Денежные действия всегда объясняют: сколько, когда резервируется/списывается и что произойдёт при отмене.
- Пустое состояние всегда содержит одно следующее действие.
- На мобильном один экран не должен одновременно содержать вкладки, фильтр, длинное пояснение и несколько CTA.

## Приоритеты

- **P0** — мешает понять действие, оплатить, сдать работу или пользоваться телефоном.
- **P1** — заметно ухудшает доверие и конверсию.
- **P2** — косметика, справка или оптимизация после появления реальных данных.

## Публичные и маркетинговые страницы

### `/` — лендинг

- Блоки: выбор роли → оффер → интерактивная демонстрация ПК → путь роли → пилот заказчика → FAQ → футер.
- Уже сделано: мобильная демонстрация скрыта, микроблок гарантий удалён, путь разделён по ролям, FAQ сокращён, форма пилота сворачивается на телефоне.
- Следующее: проверить конверсию CTA по ролям; оставить максимум четыре FAQ; реальные кейсы добавлять только после подтверждённых кампаний. **P0/P1**.

### `/business` — продукт для заказчика

- Блоки: оффер → защита бюджета → сравнение процесса → калькулятор → CTA.
- Улучшить: убрать повтор текста лендинга, свести сравнение к 3 строкам, рядом с калькулятором дать пояснение «цель, не гарантия».
- FAQ: стоимость, возврат остатка, проверка просмотров, права на ролик. **P1**.

### `/about` — о сервисе

- Блоки: обещание двум ролям → как работает → кому подходит.
- Улучшить: добавить короткую схему двух ролей и ссылку на безопасность; не повторять полный лендинг.
- FAQ не нужен; переход в `/help`. **P2**.

### `/help` — центр помощи

- Блоки: категории ответов → популярные вопросы → обращение в поддержку.
- Улучшить: поиск, переключатель роли, ссылки на конкретные действия; показывать сначала 5 популярных ответов.
- Это главный полный FAQ проекта. **P1**.

### `/help/rp` — правила RP

- Блоки: источник RP → расходование → возврат → недельные задания.
- Улучшить: таблица «купленные / бонусные», один пример операции, предупреждение о невозможности вывода бонусных RP.
- FAQ: «можно ли вывести», «что списывается первым», «где история». **P1**.

### `/safety` — безопасность

- Блоки: аккаунт → заказы → деньги → подозрительная активность.
- Улучшить: карточки угроз заменить последовательностью «риск → защита → действие пользователя».
- FAQ: потеря доступа, спор, подозрительная ссылка, заморозка выплаты. **P1**.

### `/safety/budget` — защита бюджета

- Блоки: escrow → этапы → пример расчёта → подтверждённый результат.
- Улучшить: один визуальный расчёт, единые термины «резерв / списано / свободно», ссылка на спор.
- FAQ: возврат, отмена, недобор просмотров, спор. **P0**.

### `/safety/views` — проверка просмотров

- Блоки: источники статистики → проверки → ограничения.
- Улучшить: обозначить автоматическую и ручную проверку, дату последнего снимка, причины паузы.
- FAQ: API недоступен, удалённый ролик, подозрение на накрутку, апелляция. **P0**.

### `/leaderboard` — лидеры

- Блоки: период → пьедестал → список → достижения → магазин → приглашения → коллабы.
- Улучшить: одна главная задача на мобильном; второстепенные карусели после рейтинга; карточка целиком открывает профиль.
- FAQ не нужен; достаточно подсказок к лигам и правилам периода. **P1**.

### `/store` — магазин

- Блоки: баланс → вкладки → карточки → история заявок.
- Улучшить: фильтры по типу, явные рекламные пометки, QR по запросу, короткие условия на карточке.
- FAQ: что такое RP, отмена заявки, партнёрская ссылка, обработка данных. **P1**.

### `/profiles/[handle]`, `/clippers/[handle]` — публичный профиль

- Блоки: личность → доверие → показатели → портфолио → коллаб → жалоба.
- Улучшить: единый канонический маршрут, один главный CTA по совместимости ролей, сократить декоративные статусы.
- FAQ не нужен; пояснения к проверке и коллабу показывать рядом с действием. **P1**.

### `/report/[token]` — публичный отчёт

- Блоки: итог → ссылка публикации → метрики → хронология → метод проверки.
- Улучшить: источник каждой цифры, срок действия ссылки, понятное состояние «данные обновляются».
- FAQ: почему цифры отличаются от площадки, когда обновятся, как оспорить. **P0**.

### `/legal/terms`, `/legal/privacy`, `/legal/cookies`, `/legal/community-guidelines`

- Блоки: юридические разделы и управление согласием.
- Улучшить: оглавление, дата редакции, краткое резюме простым языком, якорные ссылки.
- FAQ не смешивать с юридическим текстом; дать ссылку на `/help`. **P1/P2**.

## Авторизация и первый вход

### `/login`

- Блоки: вход → соцсети → восстановление → регистрация.
- Улучшить: одна колонка на мобильном, скрывать недоступные OAuth, объяснять причину завершения сессии.
- FAQ: только ссылка «Не получается войти?». **P0**.

### `/register`

- Блоки: имя/email/пароль → соцсети → роль → согласия.
- Улучшить: выбор роли после создания аккаунта либо одной ясной строкой; убрать обещания, не относящиеся к регистрации.
- FAQ: зачем email и можно ли сменить роль. **P0**.

### `/verify-email`

- Блоки: статус → повторная отправка → переход дальше.
- Улучшить: таймер повторной отправки и явная ошибка истёкшей ссылки.
- FAQ не нужен. **P1**.

### `/auth/continue`

- Блоки: технический переход между ролями.
- Улучшить: не показывать как самостоятельную страницу дольше 1–2 секунд; fallback-кнопка при ошибке.
- FAQ не нужен. **P1**.
